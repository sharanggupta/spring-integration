[[elasticsearch]]
= Elasticsearch Support

Spring Integration provides channel adapters (starting with version 7.3) for indexing documents into, deleting documents from, and searching documents in Elasticsearch.
It is based on the https://spring.io/projects/spring-data-elasticsearch[Spring Data Elasticsearch] project, and works with the entities that are mapped as described in the https://docs.spring.io/spring-data/elasticsearch/reference/elasticsearch/object-mapping.html[Spring Data Elasticsearch Object Mapping] chapter.

This dependency is required for the project:

[tabs]
======
Maven::
+
[source, xml, subs="normal", role="primary"]
----
<dependency>
    <groupId>org.springframework.integration</groupId>
    <artifactId>spring-integration-elasticsearch</artifactId>
    <version>{project-version}</version>
</dependency>
----

Gradle::
+
[source, groovy, subs="normal", role="secondary"]
----
implementation "org.springframework.integration:spring-integration-elasticsearch:{project-version}"
----
======

[[elasticsearch-outbound]]
== Elasticsearch Outbound Channel Adapter

The `ElasticsearchMessageHandler` is an `AbstractReactiveMessageHandler` implementation that performs an `INDEX` (the default) or a `DELETE` operation for each message against the provided `ReactiveElasticsearchOperations`.
The operation is set with the `type` option, or evaluated for each message with the `typeExpression` option, so that the same handler can index some messages and delete others.

With the `INDEX` type, the payload is saved as a document:

* An entity is saved with its Spring Data mapping, into the index of its `@Document` annotation.
* A `Map`, or a `String` with the JSON source of a document, is saved into the configured index, and Elasticsearch generates its id.
Since each save gets a new id, a redelivered message is indexed again. Use an entity with a set `@Id` property when indexing must be idempotent.
* The elements of a `Collection` payload are saved like single payloads, with one bulk request.
Without an index name, they must be entities of the same class.

With the `DELETE` type, the document with the id of the `idExpression` is deleted.
Without an `idExpression`, the payload is the entity to delete, so a `String` or `Map` payload needs an `idExpression`.
A `Collection` payload is not supported for deletion.

The `indexName` and `indexNameExpression` options set the index of the documents.
They override the index of the `@Document` annotation of an entity, and they are required for `Map` and JSON documents and for a deletion by id.

The following example indexes the payload of each message into an index per day:

[source, java]
----
@Bean
@ServiceActivator(inputChannel = "ordersChannel")
ElasticsearchMessageHandler elasticsearchIndexingHandler(ReactiveElasticsearchOperations elasticsearchOperations) {
    ElasticsearchMessageHandler handler = new ElasticsearchMessageHandler(elasticsearchOperations);
    handler.setIndexNameExpression(
            new SpelExpressionParser().parseExpression("'orders-' + T(java.time.LocalDate).now()"));
    return handler;
}
----

The following example deletes the document with the `orderId` of the payload from the `orders` index:

[source, java]
----
@Bean
@ServiceActivator(inputChannel = "cancelledOrdersChannel")
ElasticsearchMessageHandler elasticsearchDeletingHandler(ReactiveElasticsearchOperations elasticsearchOperations) {
    ElasticsearchMessageHandler handler = new ElasticsearchMessageHandler(elasticsearchOperations);
    handler.setType(ElasticsearchMessageHandler.Type.DELETE);
    handler.setIndexName("orders");
    handler.setIdExpression(new SpelExpressionParser().parseExpression("payload.orderId"));
    return handler;
}
----

The following example indexes the `Order` entities, and deletes the ones whose `cancelled` property is `true`:

[source, java]
----
@Bean
@ServiceActivator(inputChannel = "orderEventsChannel")
ElasticsearchMessageHandler elasticsearchOrdersHandler(ReactiveElasticsearchOperations elasticsearchOperations) {
    ElasticsearchMessageHandler handler = new ElasticsearchMessageHandler(elasticsearchOperations);
    handler.setTypeExpression(
            new SpelExpressionParser().parseExpression("payload.cancelled ? 'DELETE' : 'INDEX'"));
    return handler;
}
----

Like any `ReactiveMessageHandler`, the `ElasticsearchMessageHandler` is subscribed to without waiting for the result when it is used in an imperative flow.
See xref:reactive-streams.adoc#reactive-message-handler[`ReactiveMessageHandler`] for more information.

[[elasticsearch-inbound]]
== Elasticsearch Inbound Channel Adapter

The `ElasticsearchMessageSource` is a polled `MessageSource` that searches with the provided `ReactiveElasticsearchOperations` on every `receive()` call.
The payload of the produced message is a `Flux` of the documents that match the query, so the flow downstream decides how to consume them, for example with a `split()`.

The query is a `String` with the JSON of an Elasticsearch https://www.elastic.co/docs/explore-analyze/query-filter/languages/querydsl[Query DSL] query, or an `Expression` that evaluates to such a `String` or to a Spring Data Elasticsearch `Query` on every poll.
The matching documents are mapped to the `payloadType`, `Map` by default.
The `indexName` and `indexNameExpression` options set the index to search, and they are required unless the `payloadType` is an entity with a `@Document` annotation.

A JSON `String` query emits all the documents that match it.
A `Query` emits the documents of its `Pageable`, the first 10 by default in Spring Data Elasticsearch, so set a `Pageable.unpaged()` on it to emit all the matching documents.
Every poll emits the matching documents again, including those emitted by previous polls.
Use a query that selects only the documents to process, for example the ones created since the previous poll, or update the processed documents with an outbound channel adapter downstream so that they no longer match.

The following example emits the `Order` entities whose `status` is `NEW` every five seconds:

[source, java]
----
@Bean
@InboundChannelAdapter(channel = "newOrdersChannel", poller = @Poller(fixedDelay = "5000"))
ElasticsearchMessageSource newOrdersMessageSource(ReactiveElasticsearchOperations elasticsearchOperations) {
    ElasticsearchMessageSource messageSource =
            new ElasticsearchMessageSource(elasticsearchOperations, "{\"term\": {\"status\": \"NEW\"}}");
    messageSource.setPayloadType(Order.class);
    return messageSource;
}
----

[[elasticsearch-dsl]]
== Java DSL Support

The `Elasticsearch` factory creates an `ElasticsearchMessageHandlerSpec` for the `ElasticsearchMessageHandler`, with the same options as above, and with `Function` variants of the expressions:

[source, java]
----
@Bean
IntegrationFlow elasticsearchOrdersFlow(ReactiveElasticsearchOperations elasticsearchOperations) {
    return IntegrationFlow.from("orderEventsChannel")
            .channel(MessageChannels.flux())
            .handleReactive(Elasticsearch.outboundChannelAdapter(elasticsearchOperations)
                    .typeFunction(message -> ((Order) message.getPayload()).isCancelled()
                            ? ElasticsearchMessageHandler.Type.DELETE
                            : ElasticsearchMessageHandler.Type.INDEX));
}
----

The `Elasticsearch` factory also creates an `ElasticsearchMessageSourceSpec` for the `ElasticsearchMessageSource`, with a JSON `String`, a `Query`, or a `Supplier` of a `Query` that is called on every poll:

[source, java]
----
@Bean
IntegrationFlow elasticsearchNewOrdersFlow(ReactiveElasticsearchOperations elasticsearchOperations) {
    return IntegrationFlow
            .from(Elasticsearch.inboundChannelAdapter(elasticsearchOperations,
                                    () -> new CriteriaQuery(Criteria.where("status").is("NEW"), Pageable.unpaged()))
                            .payloadType(Order.class),
                    e -> e.poller(p -> p.fixedDelay(5000)))
            .split()
            .channel("newOrdersChannel")
            .get();
}
----
